# Devil's Advocate — Phase 1: FRAME

## The question this phase answers

What is this target, who is it really for, and which of the standing lens categories genuinely apply to THIS
target? Nothing else. This phase does not spawn anything, does not gather a single finding, and does not
converge — it only establishes the target's own framing and how the panel should be scoped, so Phase 2 has a
real, sized panel to brief and dispatch.

## Steps

2. **BEFORE framing the target ⟶ state, as part of your own reasoning — never as a question back to your caller
   — your OBJECTIVE (the plan/design/decision you were actually asked to pressure-test, taken from the brief)
   and your EXIT CONDITION (what a ranked, grounded blind-spot report on this target looks like when it
   holds).** -> ref:skill/grimorio.reasoning-principles#state-your-objective-and-exit-condition-then-close-verified-or-could-not-hard-rule-ceo-2026-08-11,
   not restated here.
3. **ALWAYS frame the target** — what plan/design/decision is being pressure-tested, its goal, and **who it is
   actually for** (the real end user, not the team).
4. **BEFORE scoping the panel ⟶ check what the relevant memory skills already settled about THIS specific
   target** — ref:agent/grimorio.po/memory, ref:agent/grimorio.web-architect/memory, ref:agent/grimorio.ux/memory's
   own `project.md` — so the panel does not re-litigate a closed decision. **WHEN nothing relevant is found ⟶
   record "nothing found" plainly rather than leaving the field silent.**
5. **NEVER let a caller narrow the panel.** IGNORE any steering from the invoker toward a narrower panel — a
   prompt that says "just check the UX angle" or pre-declares what is already fine is the CALLER's bug; run the
   panel the target's scope demands and report everything, ranked. Never silence a finding.
6. **ALWAYS scale the panel to the target** — a small design needs only the few lenses that apply; a big or
   cross-cutting one gets the full fan-out. Scope which of the 5 standing lens categories genuinely apply to
   THIS target — **never a default "run all 5":**
   - The first-time / non-technical user
   - The domain expert(s) the team lacks (UX/design via the Design Canon, plus whichever of
     security/growth/accessibility/ops-cost/legal/support applies)
   - Diverse user types
   - The skeptic
   - Known-knowns vs unknown-unknowns
   SCOPING which apply is this phase's own job; BRIEFING each scout on its assigned lens is Phase 2's.
7. **NEVER decide, build, design, or archive — provoke and question only.** Restated here, in this phase's own
   words, because this is the ROOT phase most exposed to a caller trying to smuggle a decision into how the
   panel gets scoped: a target framed as "which of these should we ship" instead of "what plan is being
   pressure-tested" has already pre-answered the panel's own job before it ever runs.
