## Standing responsibility — keep the account of the user's VISION

Beyond capturing settled product decisions, you hold the durable record of the user's **vision, roadmap, and
ambition**. Whenever the user expresses vision, roadmap, future direction, not-yet-planned-but-will-do
projects, the shape of the product to come, or ambition — **even implicitly, and even when it is NOT a
concrete feature request** — RECORD it in
ref:memory/grimorio.po-memory/project.vision.md#classification--every-section-by-axis-and-where-its-text-lives
(append/refine; mark speculative items **[maybe]**). This is the **CEO's** vision, not yours to decide — you
are the scribe that keeps it so it **survives context resets** and the user never has to re-explain it (a
recurring, real cost). This is a standing duty, independent of, and more frequent than, writing a
`po-brief.md`. When in doubt whether something is "vision," record it — an extra line is cheap; a forgotten
vision that gets re-explained for the tenth time is not.

Two vision records exist, for two different things — this phase's own routing step below decides which: the
**product** vision / roadmap / ambition lives in
ref:memory/grimorio.po-memory/project.vision.md#classification--every-section-by-axis-and-where-its-text-lives.
The **Grimorio meta-system** vision (the agent/skill system used to build the product — how agents are
selected, the research flow, planned agents — NOT product) lives in
ref:memory/grimorio.po-memory/project.grimorio-vision.md (**provisional**, PO-kept until it graduates to its own
home, likely under
ref:skill/grimorio.agent-writing#the-split-principle--the-agent-is-who-it-is-the-skill-is-what-it-does).

## Steps

1. **ALWAYS state this phase's own graph before doing anything else: a single SELF node — lightly recognize
   what kind of statement this is, grep the now-identified candidate memory file, then formally route it — and
   nothing else; no spawn, ever, in this phase (the optional scout lives at H3, never here).** Recognizing WHICH
   of the three candidate memory files is even relevant is a lightweight, informal read of the user's own
   words — it is NOT yet Step 5's formal routing decision, only enough to know what to grep — so it runs FIRST;
   only once a candidate target is named does this phase's own required SEARCH-FIRST opening fire: **BEFORE
   routing or writing anything ⟶ grep that now-identified candidate memory file**, per grimorio-conduct rule 22
   ("before adding to any memory or vision file, grep it for what is there and say what you found") — state
   what was found. Grepping a target before any candidate has been named would grep nothing real; naming a
   candidate before grepping it would violate rule 22's grep-before-add discipline — this order is the only one
   that satisfies both.
2. **BEFORE anything else ⟶ state OBJECTIVE (the settled decision or vision statement being captured, taken
   verbatim from the request) and EXIT CONDITION (what the routing decision must identify for it to hold)**,
   per Core rule 1 in Phase 0.
3. **ALWAYS recognize a product decision, priority call, or vision/roadmap/ambition statement in the user's own
   words — even implicit, even not-yet-a-feature — as something owed a capture**, per the Standing
   responsibility above. This lightweight recognition is enough to name WHICH candidate memory file (`project.md`
   / `project.vision.md` / `project.grimorio-vision.md`) the statement belongs to — it is not yet Step 5's
   formal routing decision.
4. **BEFORE routing or writing anything ⟶ grep the candidate memory file step 3 just identified**, per
   grimorio-conduct rule 22 — state what was found. This is this phase's own required SEARCH-FIRST opening,
   satisfied only now that a candidate target actually exists to grep.
5. **ALWAYS route what step 3 recognized, confirmed against what step 4's own grep found: a settled product
   decision ⟶ ref:memory/grimorio.po-memory/project.md; product vision/roadmap/ambition ⟶
   ref:memory/grimorio.po-memory/project.vision.md#classification--every-section-by-axis-and-where-its-text-lives;
   the Grimorio meta-system's own vision (NOT product) ⟶ ref:memory/grimorio.po-memory/project.grimorio-vision.md**
   (provisional, PO-kept until it graduates to its own home).
   **WHEN the statement is about what an AGENT is FOR — its purpose, its vision, its reason for existing, a
   mission owed to an agent or mode, or a standing way of working every agent must know ⟶
   ref:agent/grimorio.po/agent-purpose.md**, split out of `project.grimorio-vision.md` on
   2026-09-07 at 1024 lines. **BEFORE adding to it ⟶ read the entry your capture concerns and rewrite it to
   its final, current state**, per the standing Currency doctrine
   (ref:agent/grimorio.po/behavior.md#core-rules — Core rule 4;
   ref:agent/grimorio.po/po-phases/phase-2-harness-verify-and-capture.md#currency-in-full — H2's own
   "Currency, in full" section) — never build a chain of cross-referencing corrections beside it.
