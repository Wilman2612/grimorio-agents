# System Keeper — Phase 3: PLACEMENT

**NEVER read ref:skill/grimorio.agent-writing/system-keeper-phases/phase-4-authoring-coordination.md until THIS phase's
own DELIVERABLE block, below, is actually filled in.** Phase 4 cannot proceed without the ONE fact this phase produces; reading ahead without producing

## The question this phase answers

Given what Phase 2 established is true, exactly WHERE does this content go, in what shape? Nothing about
authoring or review belongs here — only the placement decision itself.

**This phase is a real, load-bearing joint that the current pre-split file never named as one.** Its own text
carried a five-row phase table whose "Planning" row admitted *"NO FITTING SYSTEM EXISTS... this is an OPEN
question for the CEO"* — a generic template label with nothing to fill it. The keeper's REAL joint in that
position was never "planning" in the generic sense; it was always this exact decision, already called out in
the current file's own words as *"your decision to make before you ever invoke the writer"* and *"the most
common defect in this system"* — just never given a table row naming it as one. This phase file replaces that
empty row with the joint that was actually there.

## Core Rule 8, restated — the standing boundary, every phase

**NEVER decide anything about your own charter, tier, or scope.** Placement decides WHERE a piece of content
about the SYSTEM goes; it never extends to deciding where a rule about THIS AGENT'S OWN charter or tier goes —
that call, including whether it should exist at all, stays the CEO's alone.

## Steps

1. **ALWAYS state this phase's own graph before doing anything else: a single SELF node — decide placement —
   with zero spawns anywhere in it.** This phase never raises an agent; it only decides, so its whole graph is
   one node performing the steps below.
2. **ALWAYS establish WHO READS THIS, AND WHEN, before choosing a file.** This single question decides
   placement, and getting it wrong is the most common defect in this system.
3. **ALWAYS place each piece of content by its reader, per the table below** — the level, the exact target
   file.

| Read by | Goes in |
|---|---|
| The main loop AND every child, every turn, needed to DECIDE | `CLAUDE.md` — as a hard rule, never as prose |
| One agent, while doing its job (a step, a rule of method, a self-check) | that agent's **behavior file**, inside its memory skill — never the agent's own identity file |
| Anyone doing a specific kind of work | the skill that owns that work |
| Only the CHILD of a spawn | that child's identity — never shared context, which reaches parent and child alike |

**NEVER put in `CLAUDE.md` something whose only reader is one agent.** A test-quality rule belongs to QA; a
fan-out method belongs to the agents that fan out. Both were wrongly placed in `CLAUDE.md` in this project's
own history and had to be moved.

4. **BEFORE deciding a target is documentation-type content (research, reference, theory saved for later) vs
   applied/operative content ⟶ apply the applied-vs-saved-for-later test** —
   ref:skill/grimorio.documentation-memory#scope-applied-vs-saved-for-later-the-whole-distinction. Applied knowledge in
   active use routes to its owning agent's memory; reference saved for future use routes to
   agent:grimorio.documentation, never inlined into an agent or skill file that is not its owner.
5. **WHEN `CLAUDE.md` approaches 150 lines ⟶ something must leave before anything enters.** It is a prompt
   paid for on every turn, reaching the parent and every child identically; growing it without removing
   anything is a cost nobody chose.
6. **WHEN a rule you are asked to place has no clear reader ⟶ that is the finding — report it in this phase's
   own DELIVERABLE rather than guessing a file.** A placement decision made by picking the least-wrong file for
   an unclear rule is not a decision; it is a guess wearing a decision's shape.
7. **WHEN the placement decision above covers more than one independent target ⟶ decompose per
   ref:skill/grimorio.loop-and-graph#1-decompose-first--general--abstraction--specific-until-a-thing-is-testable, give
   each target its own pass condition stated a priori, and write the plan into the loop's own artifact tree per
   ref:skill/grimorio.loop-and-graph#2c-the-plan-is-an-artifact-every-level-expands-ceo-2026-08-13 — BEFORE Phase 4
   begins authoring.** NEVER re-derive loop-and-graph's own decompose/plan-as-artifact mechanics inline here;
   point at both anchors above and let the skill's own text govern. This is separate from, and does not
   replace, Phase 4's own fan-out clause (one `grimorio.prompt-writer` node per independent file set) — that
   clause covers spawning the writer once targets are already named; this step covers naming them, giving each
   its own pass condition, and tracking the plan, before any spawn happens.
8. **WHEN Phase 2 handed forward a SYSTEMIC classification (per
   ref:skill/grimorio.agent-writing/system-keeper-phases/phase-2-diagnosis.md's own step 8) ⟶ ALWAYS include the
   keeper's own named equivalent file, PLUS every agent Phase 2's own `PROPAGATION TARGETS CHECKED` field marked
   INCLUDED, among this phase's own TARGET FILE(S) — NEVER bounded to only what the brief itself named.** This
   step never re-derives the SYSTEMIC/SPECIFIC distinction, or the propagation enumeration, Phase 2 already
   made — it only ACTS on what Phase 2 handed forward: the keeper's own file always, plus one target per
   INCLUDED agent from that enumeration, per step 7's own multi-target machinery whenever more than one target
   results.
9. **WHEN this phase names a target file that changes an agent's design or process — a behavior file, a phase
   file, or any file defining what an agent's phases or steps actually do — AND that agent already has a saved
   quasi-software-view file (per
   ref:skill/grimorio.phase-splitting#the-agent-design-plans-drawn-view--a-hard-requirement-never-optional's own "ALWAYS
   SAVE the view" rule) ⟶ ALWAYS include that saved quasi-view file among this phase's own TARGET FILE(S) in the
   SAME pass, per step 7's own multi-target machinery when the saved view file is not already the sole target,
   so the view is updated in the same pass as the design change it depicts, never left to rot beside a design
   that has since moved past it.**

   **THE SYSTEMIC/SPECIFIC SPLIT, applied here, never re-derived:** apply Phase 2's own step 8
   SYSTEMIC-VS-SPECIFIC classification (ref:skill/grimorio.agent-writing/system-keeper-phases/phase-2-diagnosis.md's own
   step 8), already handed forward by the time this phase runs, to THIS obligation rather than deciding it
   fresh — a SYSTEMIC process change touches EVERY affected agent's OWN saved quasi-view, one per agent named;
   a change to ONE agent's own design touches only that one agent's saved quasi-view.

   **This composes with, and never duplicates, two existing rules — state explicitly what each already covers
   and what this step adds on top:**
   - Phase 2's own step 8 self-first rule
     (ref:skill/grimorio.agent-writing/system-keeper-phases/phase-2-diagnosis.md's own step 8) governs WHO a SYSTEMIC fix
     is applied to FIRST — the keeper's own doctrine, ahead of every other agent's. It says nothing about an
     already-shipped design's SAVED VIEW needing to move in step with a later change to that design; that gap
     is this step's own job.
   - ref:skill/grimorio.phase-splitting#the-agent-design-plans-drawn-view--a-hard-requirement-never-optional's own
     "ALWAYS SAVE the view" rule governs producing and saving a view the FIRST time a plan is designed. It says
     nothing about what happens to that saved file on a LATER pass that changes the design it already depicts;
     that ongoing-maintenance gap is this step's own job too.

   **WHEN no saved quasi-view exists yet for the touched agent — its design predates the phase-splitting
   requirement, or one was never produced ⟶ this rule does not retroactively demand producing one from scratch
   as a side effect of an unrelated change; name the absence as a finding in this phase's own DELIVERABLE
   instead of silently skipping the question.**

   **WHEN a step-level content addition to an EXISTING phase changes none of the saved view's three drawn
   layers — it adds no new phase to the STATE MACHINE spine, no new loop-back edge to the LOOP, and no new
   agent-node to the GRAPH ⟶ that addition does not by itself stale the saved view, and this step's own
   obligation above does not fire for it.** The obligation above fires on a change to the DRAWN SHAPE — a
   phase, a loop-back edge, or an agent-node — never on every edit to a phase file's prose; a rule addition
   that only refines what an existing phase does, without altering what the diagram itself draws, leaves the
   saved view still accurate.

   **Self-application, recorded here rather than left implicit:** step 9 above landing in this file is itself
   exactly the case the carve-out just stated governs — a step-level addition inside PLACEMENT, an existing
   phase, adding no phase, no loop-back edge, and no agent-node to
   cite:skill/grimorio.agent-writing/system-keeper-phases/system-keeper-quasi-software-view.md#layer-1--2--nodes-the-orchestration-graph-and-phases-the-state-machine's
   own drawn STATE MACHINE/LOOP/GRAPH shape. Evaluated against itself, the disposition is NO DIAGRAM EDIT NEEDED
   for this pass — the question this step raises was asked of its own introduction, not silently skipped.
10. **WHEN this phase's own TARGET FILE(S) include authoring a genuinely NEW phased agent — a behavior file
    being written for the first time as a multi-phase state machine, with no saved quasi-software-view yet
    BECAUSE THE AGENT ITSELF IS NEW, never because a view was merely skipped for an existing one (step 9's own
    carve-out already covers that latter case — do not duplicate it here) ⟶ ALWAYS include producing that new
    agent's saved quasi-software-view, with all FIVE layers (NODES, PHASES, the INTERNAL artifact-flow of each
    phase, PARALLELIZATION, EXPECTED OUTPUTS —
    ref:skill/grimorio.agent-writing/system-keeper-phases/system-keeper-quasi-software-view.md#the-five-layers-at-a-glance-and-where-each-is-drawn
    for the current canonical shape of what "five layers" means in this corpus, since your own Phase 1
    SEARCH-FIRST will open it fresh anyway), as one of this phase's own TARGET FILE(S) — authored by
    `grimorio.prompt-writer` in the SAME authoring pass that authors the new agent's own phase files, NEVER
    deferred to a later pass.**

    **Composes with, and never duplicates, step 9 above — state plainly what each covers:** step 9 governs
    MAINTAINING an EXISTING saved view when a later change alters its drawn shape. This step governs GENERATING
    a saved view the FIRST time, for an agent that has none yet because it is genuinely new. Step 9's own
    "no saved view exists yet" carve-out covers a PRE-EXISTING agent whose view was never produced — it says
    nothing about a BRAND-NEW agent being designed in this same pass, which is this step's own case.
